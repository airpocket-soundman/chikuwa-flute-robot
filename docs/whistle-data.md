# 人の口笛のアーカイブで耳と記憶を学び直す（2026-11-25、PC のみ）

実機のマイクで録った本物の口笛は 3.5 分しかなく（目標 20 分）、step5（耳）と step6（記憶）の伸びを止めていた。
録音を増やすには実機と人が要るので、先に **公開されている人の口笛** を学習に足して、PC だけでどこまで良くなるかを見た。

## 1. 使った口笛

| データ | 中身 | 量 | 利用条件 |
|---|---|---|---|
| 実機の録音（今まで） | 録音だけモードの口笛と、口笛コピーの録音（1 人） | 約 4 分（11-24 以降に 3 本増えた） | 自分たちのもの |
| **シルボ・ゴメロ**（OpenSLR SLR137） | カナリア諸島の口笛言語。熟練者 4 人の読み上げ（話し言葉の音程の動き） | 55.5 分（fragments）。話者 04 の 7.3 分は評価用 | CC BY-NC-SA 4.0 |
| **MLEnd Hums and Whistles**（Queen Mary University of London） | 129 人が 8 曲のメロディーを口笛で（各自のスマホ・PC で録音） | 1 人 3 本まで 381 本、103 分。8 人に 1 人（16 人・15.5 分）は評価用 | **ライセンスの記載なし**（Kaggle は Unknown）。ここでの学習と評価だけに使い、音もモデルも公開しない |

ほかに探したもの: MTG-QBH（歌だけで口笛なし）、AudioSet・FSD50K の Whistling（YouTube や大きな一括配布で、取り出しにくい）、Freesound（API の鍵が要る）。

```
python scripts/archive_fetch.py silbo
python scripts/archive_fetch.py mlend --per-interpreter 3
python scripts/yamabiko_archive_whistles.py --corpus silbo
python scripts/yamabiko_archive_whistles.py --corpus mlend
```

`yamabiko_archive_whistles.py` は、アーカイブの音を **実機の録音だけモードと同じ形**（16 kHz の `pcm`・`kind="whistle"` の npz）にする。
音量は実機の口笛の中央値に合わせて 0.5〜2 倍に散らし、実機の「無音」の録音（部屋とマイクと基板の雑音）を 0.5〜3 倍で下に敷く。
評価用は名前に `_test` を付け、学習スクリプトの `--extra` が自動で外す。

## 3. 記憶（step6）

記憶は耳の内部の符号を読むので、耳を替えたら学び直す（step6.md）。同じ設定（mem_06 と同じ）で、混ぜるものだけ変えた。

| 記憶 | 耳 | 混ぜたもの |
|---|---|---|
| mem_06（今） | ear_06 | — |
| mem_08b / mem_08 | ear_06 / ear_07 | シルボ（各バッチの 25 %） |
| mem_09a | ear_08 | — |
| mem_09 | ear_08 | MLEnd（各バッチの 25 %） |

**シルボは記憶には逆効果**だった（mem_08b: 実機の口笛の思い出し 31 → 35 cent、その楽譜で吹く 36 → 24 %）。話し言葉の音程は幅が広く、
規則が笛の音域へ移すときに端を切るので、メロディーとは違う移調を教えてしまうと見ている。シルボは耳にだけ使う。

同じ評価セットでの比較（`scripts/yamabiko_memory_compare.py`、思い出した楽譜を新しいツインのまわりの 16 台で吹き、音の頭を除いて ±25 cent 以内の割合。括弧は調を除いたもの）:

| | 実機の口笛（2 本から 16 曲） | デモ動画（3 曲） | MLEnd の 16 人（40 曲） |
|---|---|---|---|
| mem_06（今） | **32 %**（42 %）、思い出しの誤差 28 cent | 3 %（73 %）、152 cent | 18 %（64 %）、77 cent |
| mem_09a | 27 %（38 %）、37 cent | 28 %（66 %）、25 cent | 18 %（65 %）、107 cent |
| **mem_09** | 24 %（39 %）、43 cent | **44 %（71 %）**、24 cent | **35 %（75 %）**、37 cent |
| 規則の楽譜で吹く（目標） | 81 % | 65 % | 76 % |

- **mem_09 は、知らない人・知らないマイクの口笛に強い**。MLEnd の 16 人では思い出しの誤差が 77 → 37 cent、調を除けば規則とほぼ同じ（75 % 対 76 %）
- **実機の口笛（本番の条件）では mem_06 の方がまだ良い**。ただし評価は同じ人の 2 本だけで、差を決めるには少ない
- どの版も、**調を除くと大きく良くなる**。残っている差の大半は移調（どの高さで吹くか）で、ここが次の課題

## 4. 判断と次

- UNO Q の耳と記憶は **替えない**（ear_06・mem_06 のまま）。ear_08・mem_09 は `runs/ear/`・`runs/memory/` に候補として残す
- 実機の口笛の録音を増やす（録音だけモード。目標 20 分）。増えたら、実機の評価を 2 本から増やして mem_06 と mem_09 を比べ直す。実機の録音を重く混ぜた mem_09 の学び直しも試す
- 移調: 記憶が「曲の音域」を覚える仕組み（今はなめらかな最高・最低音）を見直す。MLEnd の 381 本で移調だけの評価ができるようになった
- MLEnd はライセンスが不明なので、作品として公開するモデルに使うかは、作者への確認を待つ

## 5. 移調の改良（2026-11-25、mem_10・mem_11）

曲ごとの調のずれを調べると、口笛の高さ（学習で見た範囲から外れているか）とはほぼ関係がなく（相関 −0.04〜+0.40）、
**曲ごとに「音域の真ん中」を見積もるばらつき**が原因だった。今の記憶は、なめらかな最高・最低音（外れ値に引っ張られる）から、
デコーダーが移した後の音程を丸ごと出していた。そこで記憶（`score_memory.py`）に次を足した。どれも学習で決まる部分で、NumPy 版も同じ計算をする。

- **高さの分布**（`hist_bins`）: 聞いている間、学習で決まる重みで「どの高さの箱に入ったか」を足していく（曲の長さによらず大きさ一定）。規則の 2 %・98 % の点を読み取れる
- **調の頭**（`key_head`）: 分布などから移調量を出す小さな NN。規則の移調量で直接も教える。デコーダーは口笛のその時刻の音程だけを出し、
  目標 = clamp(音程 ＋ 移調量, 笛の音域)（足し算と音域への収め方は計算グラフの決まった部分）
- **固定の目盛り**（`hist_fixed`）: 分布の箱を、音の高さに対して固定の山形（96 箱、約 50 cent 刻み）にする。書き込む「音の高さのような数 p」を口笛の音程で教える（`--key-aux`）

mem_10（学習で決まる箱）では、調のずれのほとんどが調の頭の誤りから来ていて（相関 1.00）、一部の曲で 100〜340 cent 外れた。箱を固定した mem_11 で外れが減った。

```
python scripts/yamabiko_memory_train.py --ear runs/ear/ear_08.pt --keys 4096 --max-hz 15 --steps 30000 --value 128     --beta 0.08 --extremes --real runs/real/whistle_data runs/real/whistle --real-holdout 20261124_111404 20261124_111830     --demo runs/ear/demo --play runs/real/twin_y1f80_05.json --actuator models/step7c/nn_f80_t7_tw05.pt     --extra runs/archive/mlend_whistles --hist-bins 96 --hist-fixed --key-head --key-aux 1.0 --out runs/memory/mem_11
```

| 記憶 | 実機の口笛（16 曲）: 吹く（調を除く）、思い出し / ずれ除き | デモ動画（3 曲） | MLEnd の 16 人（40 曲） |
|---|---|---|---|
| mem_06（今） | 0.32（0.42）、28 / 18 cent | 0.03 | 0.18（0.64）、77 / 31 cent |
| mem_09 | 0.24（0.39）、43 / 24 | 0.44 | 0.35（0.75）、37 / 13 |
| mem_10（学習の箱＋調の頭） | 0.20（0.41）、46 / 13 | 0.22 | 0.36（0.74）、39 / 9 |
| **mem_11（固定の目盛り＋調の頭）** | **0.31（0.55）、33 / 10** | 0.37 | **0.43（0.77）、36 / 10** |
| mem_11b（p をより強く教える） | 0.12（0.44）、45 / 12 | 0.04 | 0.39（0.76）、51 / 11 |
| 規則の楽譜で吹く（目標） | 0.75〜0.81 | 0.65 | 0.77〜0.79 |

曲ごとの調のずれ（|思い出した楽譜 − 規則の楽譜| の中央値を曲ごとに）: 実機 mem_06 平均 25 / mem_11 平均 31 cent（25 cent 以内の曲 44 % / 44 %）、
MLEnd mem_06 平均 65・中央値 49 / mem_11 平均 47・中央値 23 cent（25 cent 以内 25 % / 55 %）。

- **mem_11（ear_08 と組）が全体で一番**。実機の口笛では吹く成績が mem_06 と同じくらいで、調を除いた精度は大きく良い（ずれ除き 18 → 10 cent）。知らない人の口笛では倍以上
- 調のずれはまだ残る（実機平均 31 cent、一部の曲で大きく外れる）。調を除けば規則の楽譜に近いので、残りはほぼ移調
- UNO Q にはまだ入れていない。入れるには、記憶を使う版（step6〜8、step7_practice）の耳を ear_08 に、記憶を mem_11 に替え、実機で本物の口笛を吹いて確かめる

## 6. 実機の口笛を足して追加学習（2026-11-26、mem_12b と step8p2）

11-25 の口笛コピーの録音 4 本のうち、口笛の入っていた 3 本（約 64 秒）を足した（入っていなかった 1 本は `runs/real/whistle_excluded/`）。
評価には、今までの 2 本に 11-25 の 1 本（`20261125_115203`、別の日）を加えて、学習から外した。
step8p は聞いた口笛を保存していなかったので、保存するようにした（`<日時>_whistle.npz`、口笛コピーと同じ形）。

| | 足したもの | 実機の口笛（3 本・24 曲）思い出した楽譜で吹く（調を除く） | 25 cent 以内 | デモ動画 | MLEnd の 16 人 |
|---|---|---|---|---|---|
| ear_06 ＋ mem_06（今の step8p） | — | 0.34（0.46） | 0.54 | 0.03 | 0.27 |
| ear_08 ＋ mem_11 | — | 0.35（0.51） | 0.49 | 0.37 | 0.41 |
| **ear_08 ＋ mem_12b** | 11-25 の 3 本 | **0.46（0.57）** | **0.68** | **0.51** | 0.38 |
| ear_09 ＋ mem_12 | 耳にも 11-25 の 3 本 | 0.31（0.48） | 0.39 | 0.31 | 0.38 |

- 耳（ear_09）は ear_08 と同じくらい（実機の口笛 94.2 % 対 94.0 %）。64 秒では耳は伸びず、その上の記憶はかえって悪かった
- **mem_12b が、実機の口笛で初めて mem_06 をはっきり上回った**（吹く 0.34 → 0.46、25 cent 以内 0.54 → 0.68）
- **step8p2**（`models/step8p2/`）: step8p の耳と記憶を ear_08・mem_12b に替え、終わりの判定を学び直した候補。
  シミュレーター（合成の口笛 6 曲 × 4 台 × 2 回）で 1 回目 0.388（step8p 0.342）、48 話すべて自分で止まった。
  UNO Q で聞く間 平均 7.2 ms、吹く間 平均 8.9 ms。演奏画面の版の一覧に入れた（今の版は step8p のまま）。実機で口笛を吹いて確かめる

## コンセプト

**ちくわ笛(と、その代わりになる 3D プリント笛)を、ロボットが「耳」で聴きながら吹きこなす。** 最後は人間の口笛を聴いて、数回の練習でお手本に近づけていく。

- **センシング**: マイクで自分が鳴らした音(音程・鳴っているか)を聴く。お手本として人の口笛も聴く
- **AI の判断**: 「どう動かせばどんな音が鳴るか」を学習した世界モデルと、お手本から動作プロファイルを出す強化学習の方策
- **アクチュエーション**: 吹き込み角度(サーボ)と、管に差し込むプランジャーの長さ(DC リニアアクチュエーター)

### 見せどころ

1. 新しいちくわをセットすると、最初は「スカッ」と鳴らない → 発音点を探して鳴るようになる
2. 人が口笛でフレーズを吹く → ロボットが真似る。1 回目はたどたどしい
3. 自分の音を聴き直して 2 回目、3 回目と上達する(お手本と演奏の音程軌跡を重ねて表示)
4. 別のちくわ・へたったちくわに差し替えても、数回で合わせ直す

### AI が必要な理由

- エッジに息を当てて鳴らす笛(エッジトーン)は、**吹き込み角度が「鳴る窓」を外れると急に鳴らなくなる**。窓の位置と幅は管の長さや個体で変わる
- 窓の中で角度を動かすと音程が少し変わる(ビブラートや微調整に使える)が、端に寄りすぎると途切れる
- プランジャーは位置センサーのない DC モーター駆動。不感帯・惰性・遅れ・ガタがあり、**同じ PWM でも同じ位置に止まらない**
- ちくわは個体差が大きく、使ううちにへたる。気温でも音程がずれる(約 3 セント/℃)
- こうした条件の組み合わせは固定のルールでは書き切れない。**音を聴いた結果から吹き方を学習する必然性がある**

## 学習の流れ

1. **発音補償(最小限の較正)**: ある 1 点で「鳴る角度」を探すだけ。キャリブレーションはこれ以外しない
2. **世界モデルの事前学習**: 「どう動かすと、どんな音程・発音になるか」を学ぶ。物理式(音程は管の長さに反比例)を骨格にし、実機とのずれを小さなモデルで補う
3. **ドメインランダム化**: ストロークと音程の対応、アクチュエーターの速さ・不感帯・遅れ、角度の窓の位置と幅、気温などをエピソードごとにばらつかせる
4. **お手本の自動生成(カリキュラム)**: 1 音 → 2 音の移動 → 滑らかな移動 → メロディ → ビブラート、と易しい順に
5. **強化学習**: お手本を見渡して動作プロファイル(PWM と角度の時系列)を出す方策を、世界モデルの中で大量に練習させる
6. **実機での追加学習(音感を磨く)**: 実機で吹いた記録で世界モデルを更新し、方策を学び直す
7. **ちくわへの転移**: 発音補償 1 点 + 少量の実機データで合わせる
8. **口笛の模倣と反復上達**: 吹き切って比べ、前回の結果を入力にして次のプロファイルを出す

### 2 層の制御

| 層 | 仕組み | 見えるもの |
|---|---|---|
| 基本方策(フィードフォワード) | お手本全体を先読みして、惰性や遅れを見込んだプロファイルを出す。演奏中は音を聴かずに流し切る | 回を追うごとに上達する |
| 補正方策(フィードバック) | 遅れて届く音程のずれと、自分の行動履歴から、基本プロファイルに小さな補正を上乗せ(残差強化学習) | その場で音程が寄っていく |

フィードバックの遅れは、シミュレーターにも同じ遅れを入れて学習させる。方策には「最後に聞こえた音程」と「その後に自分が出した行動」の両方を渡し、今の音程を推定させる(スミス予測器を方策が自分で学ぶ形)。

### 報酬の設計

| 項目 | 内容 |
|---|---|
| 音程誤差 | 鳴るべき区間での音程のずれ(セント)。300 セントで打ち切り |
| 無音ペナルティ | 鳴るべき所で鳴っていない(「鳴らさなければ誤差ゼロ」という抜け道を防ぐ) |
| 休符中の発音 | 休符なのに鳴っている |
| 裏返り | オクターブ上に跳んだ |
| 動きのペナルティ | 行動の急な変化。アクチュエーターの寿命と騒音対策 |

## 数字の目安

| 項目 | 値 | 根拠 |
|---|---|---|
| 音域 | 約 0.6〜1.9kHz | 片側が閉じた管: f = c / 4L、L = 4.5〜15cm |
| 10 セントに必要な精度 | 管長の約 0.58%(約 0.5mm) | 2^(10/1200) |
| 気温の影響 | 約 3 セント/℃ | 音速 c = 331.3 + 0.606T |
| 角度の刻み | 約 0.29°/段階 | SCS0009 は 300° / 1024 段階 |
| ビブラート(±2°、6Hz)に必要な角速度 | 約 75°/s | SCS0009 の能力は約 600°/s |
| 全速のプランジャーが 0.5mm 進む時間 | 約 3ms | 150mm/s |

### 音声入力の経路と遅れ

| 経路 | 聞いてから反応するまで | 使い道 |
|---|---|---|
| I2S マイク → MCU(SAI1)で音程推定 | 約 5〜15ms | 本命。フィードバック補正まで使える |
| Media Carrier のマイク端子 → PMIC → Linux(ALSA) | 約 30〜60ms | 吹き切り型の比較には十分。フィードバックは緩やかな補正のみ |
| USB マイク → Linux | 約 30〜60ms | 最後の保険 |

MCU の SAI1 ブロック A は PE5(SCK)/ PE4(FS)/ PE6(SD)で、どれも Media Carrier の JMISC ヘッダー(8 / 9 / 10 番ピン、3.3V)に出ている。ただし UNO Q の MCU で I2S マイクを動かした公開の成功例はまだ見当たらないので、最初に検証する。

## シミュレーターと強化学習環境(進捗)

このリポジトリに、numpy だけで動くシミュレーターと強化学習環境を置いた。

- **シミュレーター**: 管の共鳴(f = c / 4L、気温依存)、位置センサーのない DC プランジャー(遅れ・不感帯・惰性・ガタ)、SCS0009(0.29° 刻み・速度制限)、角度の「鳴る窓」と裏返り、音程推定のノイズと欠落
- **ドメインランダム化**: 管長・アクチュエーターの速さ・窓の位置と幅・気温などをエピソードごとにばらつかせる
- **お手本の自動生成**: 1 音 → 2 音 → 滑らかな移動 → メロディ → ビブラートのカリキュラム。口笛の音程軌跡からの変換も用意
- **3 つのモード**: 1 テイクで吹き切る / 同じお手本を複数テイク吹いて前回のずれを観測に入れる / 遅れて届く音程を観測に入れる(フィードバック)

### 最初に分かったこと

| コントローラー | 1 テイク目 | 2 テイク目 | 3 テイク目 | 5 テイク目 |
|---|---|---|---|---|
| 物理モデルだけ(学習なし) | 202 セント | 202 | 202 | 202 |
| 物理モデル + 古典的な反復学習制御(ILC) | 202 | 90 | 61 | 44 |

(ランダム化した 20 条件の平均。音程のずれの平均値)

- アクチュエーターの速さの個体差(±20%)があると、音を聴かずに推測で動かすだけでは **1 回目は平均 200 セントずれる**。これは 1 回目の中では知りようがない情報
- 前のテイクのずれを使えば、**テイクごとに確実に上達する**。「吹き切って比べて、次を直す」設計がシミュレーター上で成立した
- 次は、この上達を学習した方策(強化学習)で速める・1 テイク目から良くする段階

## UNO Q の Linux 側で動かすモデル設計

詳細は [設計メモ](uno_q_model_design.md)。要点:

- **numpy だけで推論も学習も行う**(深層学習フレームワークに依存しない)。学習は自動微分の要らない進化戦略(ES)
- **Linux 側の処理はすべて「テイクとテイクの間」に行う**。1 テイク分のプロファイルを演奏前に一括生成して MCU に送り、MCU が 100Hz で再生する。Linux の非リアルタイム性や Bridge の遅延が演奏に影響しない
- モデルは小さい: 基本方策(残差 MLP)は約 7,400 パラメーター(約 30KB)。補正方策は 1,000 パラメーター未満にして MCU に載せる
- 音程抽出は YIN。笛の音域は 16kHz で 1 セント前後の精度だが、**口笛の高音域(2.4〜3kHz)は 16kHz だと 4〜8 セントずれるので 48kHz で録る**

## リスクと最初に確認すること

- [ ] I2S マイクを MCU で受けて、音程がリアルタイムに出るか(駄目なら Linux 側の経路で進める)
- [ ] Linux → Bridge → MCU → サーボ・PWM が 100Hz で安定して動くか
- [ ] SCS0009 の半二重通信が UNO Q の MCU で使えるか
- [ ] 3D プリント笛で、角度の窓の幅・角度 1° あたりの音程変化・ストロークと音程の対応を実測する
- [ ] リニアアクチュエーターの不感帯・惰性・デューティの上限を実測する
- [ ] 世界モデル・方策が UNO Q の Linux 側で想定時間内に推論・学習できるか

## 用語メモ

- **世界モデル**: 行動からその結果(ここでは音程・発音)を予測する学習済みモデル
- **ドメインランダム化**: シミュレーターの条件をばらつかせて学習し、実機の個体差や環境の違いに強くする手法
- **反復学習制御(ILC)**: 同じ動作を繰り返しながら、前回のずれを使って次の入力を直していく制御
- **残差強化学習**: 既存の制御の出力に、学習した小さな補正を上乗せする手法
- **ハインドサイト再ラベル付け**: 狙い通りにならなかった試行も、「実際に出た結果の正解例」として学習データに使う考え方

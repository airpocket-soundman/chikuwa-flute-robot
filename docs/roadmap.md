# 進め方(ロードマップ)

生音声E2Eモデルの機能分解、段階学習、合格ゲートは [E2EフィジカルAI開発計画](e2e-development-plan.md) を参照。総合音程誤差だけで先へ進まず、記憶・音程変化理解・FF再現・差判定・FB修正・反復適応を順に検証する。

2026-09-15 に決めた、プロジェクト全体の段階です。前の段階ができてから次に進みます。

| 段階 | 内容 | 完了の目安(案) |
|---|---|---|
| 1 | **PC で強化学習して、シミュレーター上で真似できるようになる** | 学習に使っていない機体・お手本で、古典的な方法(ILC など)より有意に良く真似できる |
| 2 | **Arduino で動くくらい小さなモデルで真似できるようになる**(PC 上で) | 小さくしたモデル(量子化・蒸留)が、段階 1 のモデルとほぼ同じ精度で真似できる |
| 3 | **Arduino で実際に推論し、シミュレーターで真似する** | Arduino が推論した行動で PC のシミュレーターを動かし(ハードウェア・イン・ザ・ループ)、PC だけで動かした結果と一致する。推論が 10ms の制御周期に収まる |
| 4 | **Arduino で笛を制御し、実物で真似する** | 実物の笛(3D プリント笛 → ちくわ)で、与えたお手本を練習の回数とともに上達しながら吹ける |
| 5 | **Arduino がスピーカーから流した音(リコーダー)を聞き、シミュレーターで真似する** | マイクで聞いたリコーダーの音から、シミュレーター上で真似できる |
| 6 | **Arduino がスピーカーから流した音(いろいろな音)を聞き、真似する** | 口笛・鼻歌・鳥のさえずりなど、音色の違う音を真似できる |

「Arduino」は Arduino UNO Q を想定しています(Linux 側 QRB2210 と MCU 側 STM32U585)。どの処理をどちらに置くかは [UNO Q の設計メモ](uno_q_model_design.md) を参照してください。

## 現状(2026-09-15)

段階 1 の途中です。

- テイク間の機体推定で、2 テイク目のずれが古典的な ILC の 69 → 23 セントに下がった(学習に使っていない 100 条件)
- 演奏中に遅れて届く音を聞いて直す方策を強化学習(ES)で学習し、1 テイク目が手作りの補正の 62 → 38〜44 セントに下がった(200 条件)。記憶なし MLP・履歴つき MLP・GRU の差は小さく、100 世代で打ち切った
- お手本は 1,000 曲の固定セット(1 音 0.25 秒以上、跳躍 400 セントまで、切る・つなげる奏法)
- 音程を聞き取るネットワークを合成音で学習し、YIN を上回った(自分の耳 0.9 セント、お手本の耳はリコーダー → 口笛 → 鼻歌 → 鳥と音色を足して 0.5〜1.0 セント、前の音色を忘れない)。実機のマイクでは未確認
- **シミュレーターが甘すぎた**: 制御側が知らない効果(静止摩擦、非線形な速さ、鳴り始めの遅れ、ヒステリシス、確率的な窓の端、オクターブ誤りなど)を `harsh` で入れると、実際に鳴った音程で 2 テイク目のずれが 19 → 48 セント(機体推定 + ILC)、強化学習では 25〜28 セントになり、テイクを重ねても良くならなくなった。値は推測なので、実物の測定で合わせる必要がある
- GPU 版のシミュレーターと制御を作り(numpy 版と行動が一致)、厳しいシミュレーターで学習し直した。伸びは小さく(最良は履歴つき MLP、2 テイク目 25 セント)、耳の特徴を方策に渡す E2E 方法 A にもはっきりした効果はなかった
- 段階 2・3 の準備(実機なしで PC でできるところまで): 方策を int8 にしても精度は落ちない(3.4KB)。小さい耳(1.6 万パラメーター)は大きい耳とほぼ同じ精度。制御を C に移し、HIL の通信の仕組みを作って、PC 上の代役で numpy 版と同じ演奏になることを確認。UNO Q の実機では未確認
- 開発の経緯と聞き比べ: [history.html](history.html)

## 段階 5・6 に向けた準備(提案)

段階 5・6 では、お手本を音として聞く必要があります。そのための学習は PC 上で先に進めておく案です。

1. シミュレーターで音を合成する(済み: `flute_rl/audio.py`)
2. 音程を読み取る小さなネットワークを作り、決まった計算(YIN)と比べる
3. ロボット自身の音を、音から直接(E2E)聞いて直す方策を学習する(PyTorch・GPU)
4. お手本も音から直接受け取る。音色はリコーダーから始めて、口笛 → 鼻歌 → 鳥のさえずりと、前の音色も混ぜたまま増やしていく
5. ご自身の実際の録音で追加学習する

鳥のさえずりの方針(2026-09-15 決定): まずはウグイスの「ホーホケキョ」を想定する。テストは、ウグイスを含む真似しやすい鳴き声(例: ウグイス、カッコウ、シジュウカラの「ツツピー」)で行い、真似できないような複雑な鳴き声は対象にしない。最初は音程の形を真似て合成したお手本で試し、後で実際の録音(使用条件を確認したもの)を使う。ウグイスの「ケ」は 0.1〜0.2 秒と短く、学習用のお手本の決まり(1 音 0.25 秒以上)より速いので、真似できる範囲かをテストで確かめる。

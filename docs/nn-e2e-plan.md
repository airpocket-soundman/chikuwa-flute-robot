- これまでと同じく **1 段ずつ置き換え、毎段で実機と比べられる形を保つ**（step1→step4 のやり方）。

### 1.1 完成形の動き（目指す姿）

秒数は決めない。開始ボタンと終了ボタンだけを用意し、

1. 開始ボタンを押す → 人が口笛を吹く → 終了ボタンを押す
2. その間 NN はお手本を聞き、楽譜にして **NN の中（書き込み式の記憶 `W`）に保存**する
3. 終了ボタンの後、NN が思い出しながら演奏し、吹き終わったら自分で止まる

これを **1 つの NN（1 つの計算グラフ）** が 10 ms ごとに動いてこなす。ボタンも入力の 1 つにし、「今は聞く時か吹く時か」を NN の中で切り替える。
機械は NN の出力をそのまま受けて動くだけにする。

**入力（10 ms ごと）**

| 入力 | 中身 |
|---|---|
| マイク | 最新 20 ms（320 サンプル、16 kHz） |
| ボタン | 開始が押された／終了が押された（1/0） |
| 機械の状態 | 前回の出力、モーター電流、端のスイッチなど |
| 内部状態 | GRU の状態 `h`、お手本の記憶 `W`、機体の記憶 |

**出力（10 ms ごと）**

| 出力 | 機械側の動き |
|---|---|
| アクチュエータの PWM | そのまま駆動 |
| サーボの開閉（または目標位置） | SG90 を 1560／1820 µs の間で動かす |
| ファンのデューティ | ファンを回す |
| 終了の確率 | 演奏を終えて待機に戻る |

**流れ**

```
待機 ─[開始]→ 聞く ───────────────[終了]→ 吹く ────────────────→ 待機
              ・10 ms ごとに耳の符号を        ・W から思い出しながら
                W へ書き込む                    PWM・サーボ・ファンを出す
              ・PWM 0、弁は閉、ファン停止      ・自分の音を聞いて直す
              ・長さは決めない                 ・曲の終わりで「終了」を出す
```

- **長さを決めなくてよい理由**: `W ← W + η v_t k_tᵀ` は何ステップ書き込んでも `W` の大きさが変わらない。開始から終了まで、押された時間だけ書き込めばよい。
- **曲の位置の符号 `k_t`**: 開始からの経過時間をいくつかの周期の sin/cos にしたもの。演奏でも 0 から同じ符号で読み出せば、聞いたときと同じテンポで再生される。
- **終わりの判断**: `W` には「鳴っていたか」も入るので、最後の音が終わったことを NN が思い出して「終了」を出せる（`e2e.py` の終了確率と同じ役目）。

**気をつけること**

- **ファン**: 回り始めに数秒かかり（今は規則で 2〜3 秒先に回している）、強さで音程も変わる（50→100 % で +72 cent 以上）。
  NN が「最初の音より先に回し始める」まで学ぶ必要がある。最初は「吹く間は 80 %」をまねる出力にし、あとで自由にさせる。
  今のシミュレーターはファン 80 % か 50 % の固定なので、ファンの強さを連続で変えられる模型を足す必要がある。
- **安全のための上限は外に残す**: 長さは決めなくても、記憶の上限（例: 聞くのは最長 60 秒）は機械側に置く。PWM 上限・端での停止・通信が途切れたときの停止・非常停止も外。
- **ボタン**: 今の機体のボタンは EXEC（D8）1 つ。「1 回押して開始、もう 1 回押して終了」にするか、ウェブ画面（`scripts/yamabiko_web.py`）に 2 つ置く。NN から見れば同じ入力。
- **原点出し**: 今は演奏前に規則で戻している。NN に任せる仕組み（`NNConfig.self_home`）もあるが、まず外に残し、step7 以降で試す。
- **学習の仕方**: いきなり 1 つの NN を学習させず、部品ごとに学習してからつなぐ（step5〜8）。
  最後にシミュレーターで「待機 → 開始 → 合成の口笛 → 終了 → 演奏」という 1 話を丸ごと流し、ボタンの切り替え・ファン・終了も一緒に学ばせる（step8）。

## 2. いまの姿（step4）

### 2.1 処理の流れ

```
[お手本を聞く]  口笛の録音 ─ YIN ─ 補間・ノイズ除去・中央値 ─ 笛の音域へ移調 ─▶ 楽譜（10 ms ごとの 音程 / 鳴らすか）
                 （規則）     （規則 clean_track）           （規則 to_target）       （モデルの外の配列）

[演奏する 10 ms ごと]
   楽譜の 0〜0.7 秒先 ─┐
   ツインの推定位置 ──┤
                       ├▶ 演奏 NN ─ pwm ─▶ アクチュエータ
   マイク 20 ms ─▶ 耳 NN ─┤        │
                       └──────▶ タンギング NN ─ open_prob ─▶ 切換え弁
```

### 2.2 3 つの NN（入出力）

Netron で見た図: [耳](step4-netron/ear.png)・[演奏](step4-netron/actuator.png)・[タンギング](step4-netron/valve.png)。
ONNX は `models/step4/onnx/`、書き出しは `python scripts/export_step_models_onnx.py models/step4`
（PyTorch 不要。`*_runtime.npz` から組み立て、NumPy 版と一致するか確かめてから保存する）。

| モデル | 入力 | 出力 | 中身 |
|---|---|---|---|
| 耳 `ear_01` | `samples` (1, 320)：マイクの最新 20 ms（16 kHz、−1〜1） | `pitch_logits` (1, 96)：25 cent 刻み −600〜+1775 cent（約 310〜1250 Hz）<br>`voiced_logit` (1,)：鳴っているか | RMS 正規化 → Conv1d×3 → 全結合×2。約 12 万パラメーター |
| 演奏 `nn_f80_t4_s06` | `features` (1, 29)、`h` (1, 64) | `pwm` (1, 1)：−1〜1<br>`h_next` (1, 64) | 全結合+tanh → GRUCell → 全結合+SiLU → 全結合+tanh |
| タンギング `valve_t4_01` | `features` (1, 27)、`h` (1, 32) | `open_prob` (1, 1)：0〜1、0.5 以上で開<br>`h_next` (1, 32) | 全結合+tanh → GRUCell → 全結合+sigmoid |

`features` の中身（音程は `(cent − 中心) ÷ 幅` でそろえる）:

| 位置 | 演奏 NN（29） | タンギング NN（27） |
|---|---|---|
| 0〜9 | 楽譜の音程、0・3・6・10・15・20・30・40・55・70 ステップ先 | 同じ |
| 10〜19 | 同じ 10 か所の「鳴らすか」 | 同じ |
| 20 | 前のステップで聞こえた音程（聞こえなければ 0） | 同じ |
| 21 | 聞こえたか | 同じ |
| 22 | 今の目標 − 聞こえた音程 | 同じ |
| 23 | 前回自分が出した PWM | 演奏 NN が**今**出した PWM |
| 24・25 | ツインのモーターの式による推定位置・速度 | 同じ |
| 26 | 今鳴らすべきか | 前のステップの自分の open_prob |
| 27・28 | 目標音程・聞こえた音程に対応する位置（ツインで逆算） | — |

`h` は GRU の内部状態（これまでの経過の要約）。演奏の始めは 0、以後は前回の `h_next` を戻す。
コード: 演奏 `flute_rl/yamabiko/residual_numpy.py`（`NNRuntime.command`）、タンギング `flute_rl/yamabiko/valve_nn.py`、
耳 `flute_rl/yamabiko/ear_nn.py`。

### 2.3 耳 NN が使われている場所

演奏中のフィードバックだけ（`server.py` の `cmd_play` で `ear="nn"` のとき）。
お手本の口笛、キャリブレーション（`cmd_calibrate`）、その日のずれの測定（`cmd_tune`）は YIN のまま。
口笛を YIN にしている理由は、口笛（1〜4 kHz）が耳 NN の範囲の外で、学習データも笛の音しかないため。

### 2.4 まだ NN でない部分

| 部分 | 今の担い手 | 置き換え先 | 段 |
|---|---|---|---|
| お手本の口笛 → 音程 | YIN（`whistle.py`） | 共通の耳 NN | step5 |
| キャリブレーション・ずれの測定の音程 | YIN（`hw.py heard_pitch`） | 共通の耳 NN | step5 |
| 補間・ノイズ除去・中央値 | 規則（`clean_track`） | お手本の記憶 NN | step6 |
| 笛の音域への移調・休符の扱い | 規則（`to_target`） | お手本の記憶 NN | step6 |
| 楽譜（配列）とその先読み | モデルの外の配列 | 重みに書き込む記憶 | step6 |
| 推定位置・速度 | ツインのモーターの式 | 演奏 NN の内部状態 | step7 |
| 音程 → 位置の逆算 | ツインの物理式 | 外す | step7 |
| キャリブレーション・ツインの当てはめ | 規則＋最適化 | 機体の記憶（書き込み式） | step7 |
| 3 つの NN の間のつなぎ | Python のコード | 1 つのグラフ | step8 |
| 原点出し・PWM 上限・非常停止 | 規則 | **残す**（安全機構） | — |

### step5：共通の耳（YIN を推論から外す）

- **やること**: 耳 NN の範囲を笛＋口笛（約 310〜4000 Hz、25 cent 刻みで約 190 区分）に広げ、お手本・演奏中・キャリブレーションのすべてで同じ重みを使う。
- **意味**: お手本も自分の音も同じ耳で聞くので、マイクや部屋のくせが比較の段で打ち消される（[modular-hybrid-model-plan.md](modular-hybrid-model-plan.md) の「1 つの耳」）。
- **データ**: 実機のマイクで口笛を 10〜20 分（いろいろな高さ・跳躍・グライド・息の多い音）。ラベルは今の耳と同じく、後から長い窓の YIN と FFT のピークが一致したところだけ（`scripts/yamabiko_ear_data.py` を口笛にも使えるようにする）。録音前でも合成の口笛（sin 波＋ビブラート＋息の雑音）で仕組みは作れる。
- **注意**: 演奏中も 10 ms ごとに動くので、大きくした耳が UNO Q の時間に収まるか測る（今の耳は PC で 0.1 ms）。笛の音域での精度が step4 より落ちないこと。
- **合格の目安**: 学習に使っていない録音で、笛は step4 の耳と同等（±25 cent 以内 96 % 前後）、口笛は YIN と同等。実機の 3 曲で step4 と同等。

### step6：お手本の記憶 NN（楽譜を重みに保存する）

- **やること**: 耳の出力（音程そのものではなく耳の内部の符号）を、聞いている間に小さな行列 `W` へ書き込む。
  `W ← W + η · v_t k_tᵀ`（`k_t` は曲の中の位置の符号、`v_t` は聞いた内容の符号）。演奏中は `W k_t` で思い出し、演奏 NN の `features[0:20]` の代わりに渡す。
- **意味**: 推論の経路から「音程の列」「楽譜の配列」が消え、[e2e.md](e2e.md) の「モデルの外に音程列や楽譜を作らない」を満たす。
  「聞いたお手本はシナプスに書き込まれ、演奏で思い出す」と説明できる。補間・移調・休符処理もこの中で学ぶ。
- **既存のもの**: `beat_grid.py` の `BeatTimelineRecallNet`（NN の符号の列を保存する。配列としてはモデルの外にある）、
  `adaptive_memory.py`（曲の位置ごとの記憶スロット）。まずこれらと「重みに書き込む記憶」をシミュレーターで比べる。
- **確認用**: `W` から思い出した内容を音程に戻す補助の出力を付け、「NN が何を覚えたか」を図にする（演奏には使わない）。
- **リスク**: `W` の大きさは曲の長さによらず一定なので、長い曲ほど記憶が混ざる。どの長さまで持つかを最初に測る。
- **合格の目安**: シミュレーターで、思い出した目標で吹いたときの命中率が、今の楽譜（配列）で吹いたときと同等。

### step7：ツインに頼らない演奏 NN

- **やること**: `features[24:29]`（ツインの推定位置・速度・逆算位置）を外し、演奏 NN の GRU に自分で位置を推定させる。
  キャリブレーションとツインの当てはめの代わりに、機体のくせを書き込み式の「機体の記憶」に覚えさせる（`rig_adaptive.py` の `SlowRigMemory` が出発点）。
- **意味**: 物理式が推論から消え、「笛を替えて一度崩れ、同じ重みのまま吹くほど合ってくる」デモ（[e2e.md](e2e.md)）につながる。
- **リスク**: エンコーダーがないので、位置の推定は音程だけが頼り。シミュレーターでは「音程を位置センサーにする観測器」が最も効いていた（[modular-hybrid-model-plan.md](modular-hybrid-model-plan.md)）。NN がそれを内部で学べるかが山場。
- **合格の目安**: 実機の 3 曲で step4 と同等、または 2 回目以降に step4 へ追いつく。

### step8：1 つのグラフにする

- **やること**: 耳・お手本の記憶・機体の記憶・演奏・タンギングをつなぎ、補助の損失（音程の推定、記憶の再現）を残したまま全体を微調整する。ONNX 1 本に書き出す。
- **完成形の動きを入れる**（1.1 節）: ボタンの入力と聞く／吹くの切り替え、ファンとサーボを直接出す出力、終了の出力を足す。
  シミュレーターにファンの強さを連続で変えられる模型を足し、「待機 → 開始 → 口笛 → 終了 → 演奏」の 1 話を丸ごと学ばせる。
- **出口**: Netron で全体が 1 枚の図になる。UNO Q では PyTorch なしの NumPy で 10 ms に収まる。
  ボタン 2 つだけで、長さを決めずに聞いて、覚えて、吹ける。
- **既存の別路線との関係**: `e2e.py` の `E2EImitator` は最初から 1 モデルで学習する路線で、シミュレーターでも誤差 270 cent 台と実用前。
  step8 は「段ごとに学習済みの NN をつないでから微調整する」路線で、うまくいけば `E2EImitator` の初期値にもできる。

| 学習のログ | `runs/twin_viewer/<出力名>/step_<n>.npz` | 学習中の 13 回ほどの 128 台ぶんの演奏。`scripts/yamabiko_twin_viewer_data.py` で [ツイン学習ビューア](twin_viewer/fleet.html) に入れる |
| 推論 | UNO Q の Linux 側（NumPy） | `scripts/uno_q_push.sh` で送る |

### 4.1 128 台を標準にした理由（2026-11-25）

step7c の演奏 NN（新ツイン）を同じ曲数で比べた（評価用 48 台の誤差、採用した重み）：

| 台数 × 回数 | 学習率 | 時間 | 誤差 |
|---|---|---|---|
| 32 × 1500 | 1e-3 | 51 分 | 48.5 cent |
| 128 × 375 | 1e-3 | 12 分 | 49.9 cent |
| 128 × 375 | 2e-3 | 12 分 | 49.5 cent（まだ下がっていた） |

GPU（RTX 5060 Ti）は 32 台では 2 割ほどしか使っておらず、1 回の時間は台数によらずほぼ同じ（10 ms ずつ順に進める部分が律速）。
同じ曲数なら 4 分の 1 の時間で、精度の差は 1 cent ほど。足りなければ回数を増やす。

## 5. 用語

| 言葉 | 意味 |
|---|---|
| YIN | 波形を何サンプルずらすと自分と重なるかで基本周期を求める方法。倍音にだまされにくく、短い窓でも数 cent の精度。学習不要 |
| ツイン | 実機に当てはめたシミュレーター（デジタルツイン）。`twin_*.json` |
| 書き込み式の記憶（fast weights） | 推論中に `W ← W + η v kᵀ` で行列に書き込み、`W k` で読み出す記憶。線形の注意機構と同じ計算なので普通に学習できる |
| step | 実機で比べられる配備の単位。`models/stepN/` と `docs/stepN.md` |

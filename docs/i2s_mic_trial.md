# I2S マイクを MCU（SAI1）につなぐ — 配線と試し方

やまびこ1号のマイクを、UNO Q の **MCU（STM32U585）の SAI1**（3.3V）につなぐ。
基板を起こす前に、UNO Breakout Carrier + ジャンパ線で動くところまで確かめるための手順。

Linux 側の MI2S0（1.8V）でも動く実績がある（[`pcb_design.md`](pcb_design.md) の先例の節）。
MCU 側を本命にするのは、`idea.md:138` の「聞いてから 5〜15ms で反応する」がこちらの経路の前提だから。

## ピン指定

SAI1 のブロック A を受信（マイク）に使う。**すべて AF13**。
Zephyr の `hal_stm32` の `dts/st/u5/stm32u585aiix-pinctrl.dtsi` で確認した。

| 役割 | STM32U585 | AF | Breakout Carrier | Carrier の信号名 | INMP441 |
|---|---|---|---|---|---|
| ビットクロック | **PE5** | `sai1_sck_a` AF13 | **J15-8** | `MCU_TRACE_D2 / PE5` | SCK |
| ワードセレクト | **PE4** | `sai1_fs_a` AF13 | **J15-9** | `MCU_PSSI_D4 / PE4` | WS |
| データ（入力） | **PE6** | `sai1_sd_a` AF13 | **J15-10** | `MCU_TRACE_D3 / PE6` | SD |
| 電源 3.3V | — | — | **J14-13** または **J14-15** | `+3V3` | VDD |
| GND | — | — | **J15-23**（近い）、J15-30、J15-40 | `GND` | GND, L/R |

- **L/R は GND へ**（左チャンネル。WS が Low の区間にデータが出る）
- INMP441 の VDD は 1.8〜3.3V なので **3.3V で直結できる**。レベル変換は不要
- SD にプルダウン 100kΩ を入れる（相手が出力していない半フレームで線が浮くため）
- SCK / WS / SD に直列 33Ω。配線は 20cm 以内

### 使わないが出ている SAI1 のピン

あとで「鳴らす側」や MCLK が要るマイクに替えるときのために控えておく。

| 信号 | ピン | AF | Carrier |
|---|---|---|---|
| `SAI1_MCLK_A` | PE2 | AF13 | J15-4（`MCU_TRACE_CLK`） |
| `SAI1_SD_B` | PE3 | AF13 | J15-6（`MCU_TRACE_D0`） |
| `SAI1_SD_B`（別割当） | PE7 | AF13 | J15-12（`MCU_PE7`） |
| `SAI1_SCK_B` | PE8 | AF13 | J15-14（`MCU_PE8`） |

ブロック B（PE3 / PE7 / PE8 / PE9 / PE10）が丸ごと空いているので、
将来「聞かせた音を鳴らし返す」構成にしても、ブロック A の受信とぶつからない。

## SAI の設定

| 項目 | 値 | 理由 |
|---|---|---|
| モード | マスター受信 | マイクがスレーブ。SCK / WS は STM32 が出す |
| プロトコル | I2S（Philips）、FS は Low で左 | INMP441 は L/R = GND で左 |
| スロット | 2 スロット × 32bit | INMP441 は 32bit フレームに 24bit を MSB 詰めで出す |
| データ長 | 24bit | 下位 8bit は 0 |
| サンプリング | **48kHz** | SCK = 48k × 64 = **3.072MHz**。INMP441 の許容は 0.5〜3.2MHz なので上限に近いが範囲内 |
| 転送 | DMA 循環バッファ | 10ms（480 サンプル）ごとに半転送割り込み |

16kHz にすると SCK は 1.024MHz に下がって楽になるが、`flute_rl/pitch.py` の
既定フレーム 1024 サンプルが 64ms になってしまう。48kHz なら 21ms で、
やまびこの遅れの予算（`yamabiko.md` の開ループ誤差予算、休符 50〜120ms）に収まる。

## 試す順番

1. **ピンの導通確認。** Carrier に何も載せず、J15-8 / 9 / 10 と J14-13、J15-23 をテスターで当たる。
   **J14/J15 は嵌合面で左右が反転する**（IchiPing-UNO-Q が一度間違えた箇所）。ピン 1 の位置を上面図と照合してから配線する。
2. **マイクへ電源だけ入れる。** 3.3V と GND、L/R = GND。消費電流が数 mA であることを確認（INMP441 は約 1.4mA）。
3. **SCK / WS を出すだけ。** SAI をマスター送信相当で回し、オシロで 3.072MHz と 48kHz を確認。
   マイクは SD を出し始める。**信号線をつなぐ前に電源を入れる**（先例の安全則）。
4. **SD を取り込む。** DMA で 1 秒ぶん取り、無音時の値が 0 付近か、指で叩いて振れるかを見る。
5. **音程が出るか。** 取った波形を Bridge 経由で Linux 側へ渡し、`flute_rl/pitch.py` の `pitch_track` にかける。
   440Hz の音叉かスマホの発振アプリで、読みが合うかを確認する。
6. **遅れを測る。** これがこの試みの本題。スピーカーから短いトーンを出し、
   MCU が「音程が確定した」と判断するまでの時間を D ピンのトグルで出してオシロで測る。
   `idea.md:138` の 5〜15ms に収まるかどうかで、やまびこの制御の組み方が決まる。

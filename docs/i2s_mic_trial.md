# I2S マイクを MCU（SAI1）につなぐ — 配線と試し方

やまびこ1号のマイクを、UNO Q の **MCU（STM32U585）の SAI1**（3.3V）につなぐ。
基板を起こす前に、UNO Breakout Carrier + ジャンパ線で動くところまで確かめるための手順。

Linux 側の MI2S0（1.8V）でも動く実績がある（[`pcb_design.md`](pcb_design.md) の先例の節）。
MCU 側を本命にするのは、`idea.md:138` の「聞いてから 5〜15ms で反応する」がこちらの経路の前提だから。

## ピン指定

SAI1 のブロック A を受信（マイク）に使う。**すべて AF13**。
Zephyr の `hal_stm32` の `dts/st/u5/stm32u585aiix-pinctrl.dtsi` で確認した。

| 役割 | STM32U585 | AF | Breakout Carrier | Carrier の信号名 | ICS-43434 |
|---|---|---|---|---|---|
| ビットクロック | **PE5** | `sai1_sck_a` AF13 | **J15-8** | `MCU_TRACE_D2 / PE5` | SCK |
| ワードセレクト | **PE4** | `sai1_fs_a` AF13 | **J15-9** | `MCU_PSSI_D4 / PE4` | WS |
| データ（入力） | **PE6** | `sai1_sd_a` AF13 | **J15-10** | `MCU_TRACE_D3 / PE6` | SD |
| 電源 3.3V | — | — | **J14-13** または **J14-15** | `+3V3` | VDD |
| GND | — | — | **J15-23**（近い）、J15-30、J15-40 | `GND` | GND, L/R |

- **L/R は GND へ**（左チャンネル。WS が Low の区間にデータが出る）
- ICS-43434 の VDD は **1.65〜3.63V** なので **3.3V で直結できる**。レベル変換は不要
- **SD に 100kΩ プルダウン**（データシート指定。SD は LSB を出した直後にトライステートするため）
- SCK / WS / SD に直列 33Ω
- **VDD 直近に 0.1µF の X7R 以上**。ビアを挟まず同一層で最短に（データシート指定）
- LR は **内部に 100kΩ プルダウンがある**ので、左チャンネルなら開放でも成立する。ただし確実を取って GND へ落とす

### ICS-43434 のデータシートから確定した値

`datasheets/ICS-43434-datasheet-v1.2.pdf`（DS-000069 Rev 1.2）より。

| 項目 | 値 | 効いてくるところ |
|---|---|---|
| **サンプリング周波数** | High-Performance **23〜51.6kHz** / Low-Power 6.25〜18.75kHz / Sleep < 3.125kHz | **16kHz は High-Performance の範囲外**。48kHz を選ぶ理由がこれで確定した |
| **SCK 周期** | 303〜2500ns = **400kHz〜3.30MHz** | 48kHz の 3.072MHz は上限の 93%。**44.1kHz へ落とす余地はあるが、上へは伸ばせない** |
| フレーム | **64 SCK / WS フレーム**、24bit 二の補数、MSB first | SAI は 2 スロット × 32bit、データ 24bit |
| L/R | Low = 左（**WS の立ち下がり後**にデータ）。内部 100kΩ プルダウン | GND へ |
| **起動時間** | クロック開始から **32,768 SCK = 10.7ms** で出力開始。感度が 1dB 以内に落ち着くまで **最大 20ms** | **これが致命的**。下記「SCK を止めない」 |
| スリープ | fS < 3.125kHz で 1ms 以内にスリープ、12µA | |
| 消費電流 | High-Performance 490µA(typ) / 550µA(max) | 手順 2 で見る値 |
| SD の駆動能力 | **85pF 負荷まで**。トライステート時の容量は約 6pF | **ケーブルを引き回せない根拠**。より線は 50〜100pF/m 程度なので、20cm で 10〜20pF。ここは余裕がある |
| 出力レベル | VOH ≥ 0.65 × VDD（3.3V で 2.15V）、VOL ≤ 0.35 × VDD | STM32U585 の VIH を確認する。一般的な STM32 の 0.45VDD+0.3 = 1.79V なら通る |
| ボトムポート | 音の入口は部品の裏 | **ブレークアウトを使うので基板側の音孔・ガスケットは不要**。ただしモジュールの穴が開いた面を笛へ向ける |
| SNR | 65 dBA | INMP441（61 dBA）より良い。音程のゆらぎ＝位置センサーのノイズなので素直に有利 |
| ハイパスフィルター | −3dB が 24Hz | 狙いの 650〜1350Hz には影響しない |

### SCK を止めない

**電源投入時に SAI を回し始めたら、演奏中はもちろん曲と曲の間も SCK を止めない。**

止めると復帰に **10.7ms（出力開始）〜20ms（感度が整う）** かかる。
`idea.md:138` の「聞いてから 5〜15ms」はこれだけで消し飛ぶし、
やまびこの休符は 50〜120ms（`yamabiko.md` の開ループ誤差予算）なので、
「鳴っていない間だけ止める」ような節電は成立しない。消費電流は 550µA なので止める利得もない。

止めるのは電源を落とすときだけ。止める場合は SCK と WS の両方を止めて GND へ引く（データシート推奨）。
**VDD が無い状態でクロックを入れてはいけない**とも明記されているので、手順 2 → 3 の順は守る。

### 使わないが出ている SAI1 のピン

あとで「鳴らす側」や MCLK が要るマイクに替えるときのために控えておく。

| 信号 | ピン | AF | Carrier |
|---|---|---|---|
| `SAI1_MCLK_A` | PE2 | AF13 | J15-4（`MCU_TRACE_CLK`） |
| `SAI1_SD_B` | PE3 | AF13 | J15-6（`MCU_TRACE_D0`） |
| `SAI1_SD_B`（別割当） | PE7 | AF13 | J15-12（`MCU_PE7`） |
| `SAI1_SCK_B` | PE8 | AF13 | J15-14（`MCU_PE8`） |

ブロック B（PE3 / PE7 / PE8 / PE9 / PE10）が丸ごと空いているので、
将来「聞かせた音を鳴らし返す」構成にしても、ブロック A の受信とぶつからない。

## SAI の設定

| 項目 | 値 | 理由 |
|---|---|---|
| モード | マスター受信 | マイクがスレーブ。SCK / WS は STM32 が出す |
| プロトコル | I2S（Philips）、FS は Low で左 | ICS-43434 は L/R = GND で左 |
| スロット | 2 スロット × 32bit | ICS-43434 は 32bit フレームに 24bit を MSB 詰めで出す |
| データ長 | 24bit | 下位 8bit は 0 |
| サンプリング | **48kHz** | SCK = 48k × 64 = **3.072MHz**。ICS-43434 の SCK 上限 3.30MHz の 93%、High-Performance 範囲（23〜51.6kHz）の中 |
| 転送 | DMA 循環バッファ | 10ms（480 サンプル）ごとに半転送割り込み |

16kHz は選べない。ICS-43434 の High-Performance モードは 23kHz からで、
16kHz は Low-Power モード（SNR が落ちる）に入ってしまう。
48kHz なら `flute_rl/pitch.py` の既定フレーム 1024 サンプルが 21ms で、
やまびこの遅れの予算（`yamabiko.md` の開ループ誤差予算、休符 50〜120ms）にも収まる。
クロックを落としたいときの逃げ道は 44.1kHz（SCK 2.822MHz）まで。

## 試す順番

1. **ピンの導通確認。** Carrier に何も載せず、J15-8 / 9 / 10 と J14-13、J15-23 をテスターで当たる。
   **J14/J15 は嵌合面で左右が反転する**（IchiPing-UNO-Q が一度間違えた箇所）。ピン 1 の位置を上面図と照合してから配線する。
2. **マイクへ電源だけ入れる。** 3.3V と GND、L/R = GND。消費電流を確認（490µA typ / 550µA max）。
   **VDD が無い状態で SCK / WS を入れない**（データシートが明示的に禁じている）。
3. **SCK / WS を出すだけ。** SAI をマスター送信相当で回し、オシロで 3.072MHz と 48kHz を確認。
   マイクは SD を出し始める。**信号線をつなぐ前に電源を入れる**（先例の安全則）。
4. **SD を取り込む。** DMA で 1 秒ぶん取る。**クロック開始から 10.7ms は無音、20ms までは感度が整っていない**ので、
   先頭 20ms は捨てる。そのうえで無音時の値が 0 付近か、指で叩いて振れるかを見る。
5. **音程が出るか。** 取った波形を Bridge 経由で Linux 側へ渡し、`flute_rl/pitch.py` の `pitch_track` にかける。
   440Hz の音叉かスマホの発振アプリで、読みが合うかを確認する。
6. **遅れを測る。** これがこの試みの本題。スピーカーから短いトーンを出し、
   MCU が「音程が確定した」と判断するまでの時間を D ピンのトグルで出してオシロで測る。
   `idea.md:138` の 5〜15ms に収まるかどうかで、やまびこの制御の組み方が決まる。
